채팅·문서 공동편집·등급별 게시판·전자결재·근태에 사내 문서를 근거로 답하는 AI 어시스턴트를 합친 15명 규모 사내 협업툴.

문제
업무 대화와 문서가 외부 SaaS 여러 곳에 흩어져 있었고, 회사 문서를 알고 답해 주는 AI 가 없었습니다.
해결
자체 서버 한 대에 모으고, 문서·게시글·결재·근태를 도구로 읽는 AI 어시스턴트를 얹었습니다. AI 호출은 provider 모듈 한 곳으로만 나가게 경계를 두어 공급자를 바꿔도 나머지 코드는 그대로입니다.
343백엔드 테스트 함수
아키텍처. FastAPI 프로세스 하나가 REST · WebSocket(채팅·알림·presence) · Yjs 릴레이(pycrdt)를 함께 담고, PostgreSQL 16(FTS tsvector 생성 컬럼 + pgvector) · Redis(세션·presence) · MinIO(첨부) 를 쓴다. Caddy 가 TLS 와 정적 프론트를 맡고, 외부 접속은 Tailscale. AI 호출은 app/ai/provider.py 한 곳으로만 나가고, 임베딩은 사내 Ollama 의 bge-m3. 답변 생성은 백그라운드 태스크가 DB 에 쓰고 WebSocket 은 구독만 한다. 권한 판정은 서비스 계층 함수 한 곳(can_view_*)으로 모아 REST·검색·AI 도구가 같은 함수를 부른다. Alembic 마이그레이션, pg_dump 일일 백업, Prometheus 지표, Docker Compose 로 서버 한 대에 배포.

  • 2인 트렁크 운영. OpenAPI 계약 테스트로 FE↔BE 명세가 최신인지 CI가 검사합니다. 사람 대신 AI 교차 리뷰를 거쳐 self-merge하고, 하루 9~12건 PR 을 머지한 날도 있습니다. 계약이 바뀌면 당일 프론트가 인수하는 이슈 체계를 운영했습니다.

강아지 사진 한 장을 AI 스타일 이미지로 바꿔 주고, 그 경험을 크레딧 보상으로 쇼핑몰 구매까지 잇는 웹 서비스.

문제
신생 브랜드라 쇼핑몰로 사람을 데려올 장치가 필요했습니다.
해결
로그인 없이 바로 써 보는 게스트 체험을 앞에 두었습니다. 크레딧은 쇼핑몰 연동 +3, 주문 +20을 줘서 연동과 구매로 이어지게 했습니다.
결과
결과물 품질은 만족할 만큼 나왔고 7일간 실생성 72건까지 확인했지만, 홍보 채널과 마케팅 지식이 없어 트래픽을 만들지 못했습니다. 제품은 완성됐는데 사람이 오지 않아 접었고, 서버도 내렸습니다.
$0.211→$0.053이미지 1장 생성 단가 · 약 4배 절감
아키텍처. api 컨테이너(FastAPI·Tortoise ORM) 와 worker 컨테이너가 PostgreSQL 하나를 큐로 공유한다. 업로드·품질 체크 → jobs 행 삽입 → 워커가 FOR UPDATE SKIP LOCKED 로 집어 lease 를 걸고 fal 경유 GPT Image 호출 → 결과 1장을 Cloudflare R2 에 저장 → 클라이언트는 HTTP 폴링. 크레딧은 credit_ledger append-only, 잔액은 SUM. 카페24 주문 웹훅 → dedupe_key 로 적립, 실패·안전 차단 → refund 행. 2GB VPS 한 대에 Docker Compose + Caddy, 5분 주기 운영 모니터링 웹훅(대기열·워커 사망·메모리·디스크).

  • 이미지 모델 단가 4배 절감. fal 경유 GPT Image 로 바꾸고 quality 를 명시해 장당 $0.211 → $0.053 으로 낮췄습니다. 안전필터 차단·생성 실패는 크레딧을 자동 환불해 사용자가 손해 보지 않게 했습니다.
  • Postgres 잡 큐. Redis를 기각하고 Postgres로 큐를 만들었습니다. 두 워커가 같은 잡을 집는 레이스를 SKIP LOCKED와 상태 전이를 한 트랜잭션으로 묶어 고쳤습니다. 워커를 늘려도 따로 조율할 필요가 없습니다.
  • 크레딧 원장. 지우지 않고 쌓기만 하는 원장에 dedupe_key로 멱등성을 보장했습니다. 생성 실패나 안전 차단 시에는 자동으로 환불합니다.
  • 외부 제약을 실측으로 확인하고 재설계. 카페24 OAuth가 운영자 전용이라 고객 계정은 연동할 수 없다는 걸 확인했습니다. Admin API로 회원을 조회한 뒤 SMS OTP로 본인을 확인하는 방식으로 바꿨습니다.

잡 큐 — Redis 없이

  1. 집기SELECT … FOR UPDATE SKIP LOCKED LIMIT 1 과 status→running, locked_by, locked_until 갱신을 한 트랜잭션에
  2. lease워커가 죽으면 locked_until 이 지나 다른 워커가 집음. 하트비트로 연장
  3. 완료UPDATE … WHERE locked_by=나 AND locked_until>now(). 조건 불일치면 내 결과를 버림(중복 완료 방지)
  4. 동시 처리WORKER_CONCURRENCY 로 프로세스 안 asyncio 동시 실행. 외부 API 대기가 대부분이라 워커 수를 늘리기 전에 이걸로
  5. 실패예외·안전 차단은 failed + 사유 저장 + 크레딧 자동 환불
  6. 한계 기준초당 수백 잡 또는 워커 수십 개가 되면 Redis Streams 로. 문서에 적어 둠

크레딧 원장 (ADR-01·02)

  • append-only 수정·삭제 없음. 잔액은 SUM, 캐시 잔액과 원장 SUM 을 비교하는 검증 쿼리

설계 원칙 — 다섯 프로젝트에서 반복한 것

불변식은 DB 가 지킨다정확히 한 번 발송은 partial unique index, 가입 중복은 UNIQUE + 409, 크레딧은 append-only 원장과 dedupe_key. 앱 코드가 실수해도 DB 가 거부합니다.
Postgres 하나로 충분하면 그걸로Redis 없이 FOR UPDATE SKIP LOCKED 잡 큐, FTS + pgvector 하이브리드 검색, 원장·감사 로그까지. 워커를 분리할 기준은 문서에 적어 두고, 그 전까진 인프라를 늘리지 않습니다.
비싼 모델은 파이프라인 맨 끝에정적 HTML → 헤드리스 → OCR → API → Claude Vision. 앞에서 찾으면 멈춥니다. LLM 은 규칙이 못 푸는 분류·중재에만, 결과는 캐시해 멱등하게.
권한은 서버가 판정한다프론트의 마스킹은 편의일 뿐, 차단은 API 의 403. 검색 결과의 권한 필터는 SQL 안에서, AI 도구도 질문자 권한 그대로. 전부 계정 4종 × 엔드포인트 매트릭스 테스트로 고정.
측정하고 바꾼다EXPLAIN ANALYZE 로 상관 서브쿼리 24,470회를 찾아 12배, 영상 모델 4회 교체, 이미지 단가 4배 절감. 바꾸기 전 수치와 바꾼 뒤 수치를 같이 남깁니다.
키 없이도 전 구간이 돈다외부 API 파이프라인은 dry-run 이 기본값, CI 는 실키 없이 끝까지. OpenAPI 계약 테스트가 FE↔BE 명세 어긋남을 타입 단계에서 잡습니다.

sns댓글봇

개발 완료 · Meta 검수 통과 · 실사용 안 함
2026.07 – 09백엔드 전담 · 2인 팀(프론트 1)

SNS와 커뮤니티에서 키워드 게시글을 감지해 모으고, 사람이 승인해야만 답글이 나가는 소셜 리스닝 도구.

문제
처음 요청은 댓글을 자동으로 뿌리는 봇이었습니다. 플랫폼 약관 위반, 스팸, 여론조작 위험이 컸습니다.
해결
사람 승인형으로 범위를 다시 정하고 요청자와 합의했습니다. 자동 발송 경로는 코드에 아예 만들지 않았습니다.
결과
개발을 끝내고 Meta 앱 검수까지 통과해 정상 동작합니다. 그러나 사람이 건건이 승인해 다는 답글로는 유입 효과가 나지 않는다고 판단해 실사용하지 않기로 했습니다.
2 → 1동시 승인 2건이 발송 1건으로 처리됨
5종수집 소스 · Threads·네이버·카페·커뮤니티
106건첫 실환경 조정에서 매칭한 게시글
8건설계 리뷰 MUST-FIX 반영
  • DB가 보증하는 정확히 한 번 발송. 승인 시 CAS로 클레임하고, 발송 기록에 partial unique index를 걸었습니다. sending에 멈춘 건은 sweep으로 회수합니다.
  • Meta 앱 검수 통과. Threads 권한 6종을 신청해 재반려를 거쳐 승인받았습니다. 자동 발송 없는 사람 승인형 구조가 심사 근거가 되었습니다.
  • 자격증명 구조적 보호. 토큰은 별도 테이블에 Fernet으로 암호화하고 MultiFernet으로 키를 회전합니다. 응답·로그·URL에 노출되지 않는 것을 테스트로 고정했습니다.
  • 최소 아키텍처. 별도 워커, Redis, JWT를 과설계로 기각하고 Postgres와 프로세스 안 스케줄러로 운영합니다. 워커를 분리할 부하 기준은 미리 문서로 정해 두었습니다.

저는 회사에서 가장 값싼 노동력으로 시작했습니다. 2026년 5월, 전 세계 기업의 IR 연락처를 손으로 찾아 엑셀에 붙여 넣는 아르바이트가 첫 직함이었습니다. 저를 포함한 7명이 엑셀 한 장을 놓고 기업 이름을 검색하고, 홈페이지를 찾고, 중복인지 확인하고, 연락처를 검증했습니다. 하루 200~300건. 3주쯤 하자 같은 질문이 맴돌았습니다. 검색하고 복붙하는 건 판단이 아니라 반복이고, 반복은 기계의 몫입니다. 그래서 회장님께 "인건비 절반으로 줄여 드리겠다"고 기안했습니다. 제가 하던 일을 스스로 없애겠다는 제안이었습니다.

그런 말을 할 수 있었던 건 누띠에서 한 번 증명했기 때문입니다. 회사 사이드 프로젝트로 반려견 간식 브랜드를 "해볼 사람"을 구하길래 손을 들었는데, 개발팀이 없었습니다. 입사 첫날 Notion 에 일일보고·스크럼·주간보고 체계를 세우고 커밋 기반으로 자동화했고, 간식 계산기와 카페24 쇼핑몰을 직접 만들었고, OEM 소싱과 통신판매업 신고까지 했습니다. 저는 코딩을 1년 배웠고 현업 경험이 없었지만, AI 를 팀원처럼 쓰면 경험의 공백을 실행력으로 메울 수 있다는 걸 거기서 체감했습니다.

Lead-Crawler 는 그 약속의 결과입니다. 6월 18일 기안, 7월 초 사내망 배포. 발견(국내외 공시·명부 18개국, 커서 저장·병렬) → 도메인 해석(검색 3단계 폴백, 애매하면 LLM 중재) → 실존 확인 → 연락처 5단계 추출(정적 HTML → 헤드리스 → OCR → API → Claude Vision, 앞에서 찾으면 멈춤) → 검수 큐. 비싼 모델은 맨 끝에만 두고, 워치독·재시작 재개·월 예산 가드·dry-run 기본값으로 무인 운영했습니다. 7명이 하던 일을 3명이 하고, 월 인건비는 1,000만 원에서 400만 원이 됐습니다. 운영하면서 검수 큐 조회가 2.4만 행에서 느려져 EXPLAIN ANALYZE 로 상관 서브쿼리 24,470회를 찾아 LEFT JOIN 으로 884ms → 73ms 로 줄였고, 비용 원장 버그로 디스패치가 이틀 멈춘 뒤엔 "안전장치가 작동한 것도 알림이 가야 한다"를 배웠습니다. 효과는 제가 아니라 검증팀이 자기 보고서로 쟀습니다. 수작업 추출 998건 → 0건, 검증 처리량 +57%.

실패도 있었습니다. 같은 시기에 브랜드로 사람을 데려오려고 AI 쇼츠 자동 제작, 승인형 SNS 답글, 강아지 사진 놀이터를 만들었습니다. 셋 다 기술은 돌아갔습니다. 영상 모델을 네 번 바꿔 편당 $1.45 까지 내렸고, 정확히 한 번 발송을 partial unique index 로 보증했고, 놀이터의 잡 큐는 Redis 없이 SKIP LOCKED 로 풀고 크레딧은 append-only 원장으로 불일치 0건을 만들었습니다. 그런데 사람이 오지 않았습니다. 만드는 쪽은 자동화됐는데 보는 사람을 모으는 쪽은 개발로 풀 문제가 아니었습니다. 비용·생성 건수·트래픽을 보고 셋 다 접었고, 거기서 만든 fail-safe 팩트체크·비용 원장·큐 설계는 사내 서비스로 가져갔습니다.

제니스도 자발적인 기안이었습니다. 회사는 종이 결재였습니다. 결재 하나 받으려면 이사, 대표 자리를 차례로 찾아다녀야 했습니다. 채팅·Yjs 공동편집·등급별 게시판·전자결재·근태를 한 앱에 모으는 협업툴을 기안하고, 회사 문서를 근거로 답하는 AI 어시스턴트를 얹었습니다. FTS 와 pgvector 를 RRF 로 합친 하이브리드 검색에 각주를 달고, AI 가 쓰는 도구는 일반 API 와 같은 권한 함수를 호출하게 해 질문자 권한 밖은 코드로 못 보게 했습니다. 처음엔 로컬 LLM 으로 가려 했지만 GPU 와 제 배움이 부족해 실측 끝에 Claude API 로 바꿨고, 그때 바뀐 건 provider 모듈 하나였습니다. JWT 헤더는 쿠키 세션으로 옮기고 refresh 회전·CSP·Clear-Site-Data 를 넣었습니다. 프론트 1명과 2인 트렁크, 사람 상호 리뷰 없이 AI 교차검증과 OpenAPI 계약 테스트로 하루 9~12건을 머지합니다. 백엔드 테스트 343개, 지금은 라이브 테스트 중입니다.

이 방식을 혼자 쥐고 있지 않았습니다. 디자이너와 합류한 프론트엔드 개발자를 직접 온보딩하고 AI 를 팀원처럼 부리는 법을 교육했습니다. 그 뒤로 팀 전체의 속도가 눈에 띄게 올라갔습니다. 저 혼자 빨라지는 게 아니라 팀이 그렇게 일하도록 세팅하는 것, 저는 그게 더 큰 레버리지라고 믿습니다.

코드 대부분은 Claude Code 로 짓습니다. 제 일은 무엇을 만들지 정하고, 데이터 흐름과 실패 경로를 설계하고, 나온 코드를 리뷰·테스트·운영으로 검증하는 것입니다. AI 가 짠 코드가 왜 안 도는지 잡는 건 제 몫이었습니다. yuv444p 출력으로 재생이 안 되던 회귀, 잡 조회와 lease 획득이 별도 트랜잭션이라 두 워커가 같은 잡을 집던 레이스, 정렬 키에 숨은 상관 서브쿼리. 전부 AI 가 짜고 제가 찾았습니다. 낭비를 발견하면 기계를 만들고, 사람에게는 판단만 남깁니다. 제가 하던 일을 없애는 것도 주저하지 않습니다.

이직하려는 이유는 하나입니다. 지금 회사엔 사수도 CTO 도 없습니다. 반년 동안 혼자 결정하고 혼자 책임지며 여기까지 왔지만, 제가 내린 설계 판단이 맞는지 봐 줄 사람이 없었습니다. 실행력은 증명했으니, 이제 그 실행이 올바른 방향인지 가르쳐 줄 수 있는 팀에서 제대로 배우고 싶습니다.
